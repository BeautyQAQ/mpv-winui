# Veyra 播放时窗口栏自动隐藏（2026-11-14）

用户要求播放时窗口顶栏和底栏一起自动消失，并选定英文品牌 Veyra。此前页面顶部入口与底部控制条已有 3 秒闲置计时，原生窗口标题栏没有跟随；本次把三者接入同一可见状态。

## 行为约定

- 播放时连续 **3 秒**没有操作，隐藏原生标题栏、页面顶部入口和底部控制条。窗口模式保留可缩放的边框，全屏仍使用既有全屏窗口模式。
- 鼠标实际移动、点击或键盘输入立即恢复控制栏，并重新计算闲置时间。
- 暂停、停止、播放结束、错误、加载/缓冲，以及打开菜单或面板时保持可见。
- 鼠标悬停控制区、窗口标题栏或边框，拖动/缩放窗口、拖动进度、持续按住控件或用键盘操作控件时不隐藏；操作结束后再开始闲置计时。
- 标题栏显隐引起的客户区变化不算真实鼠标移动，避免静止时反复显隐。
- 控件隐藏时，首次 Tab 恢复控件并聚焦「打开文件」；Shift+Tab 聚焦「全屏」。键盘焦点留在控件内时保持可见，回到视频区域后重新计时。

3 秒是本项目的交互约定，不是统一行业标准。播放器通常使用几秒级闲置时间，例如 [Video.js 官方源码](https://docs.videojs.com/player.js.html) 的默认 `inactivityTimeout` 为 2000 ms；这里保留已有 3 秒，给桌面鼠标与触控操作留出余量。

## 实现范围

`MainWindow` 负责原生标题栏及非客户区输入，`PlayerPage` 负责页面输入和计时，`PlayerChromePolicy` 集中判定是否允许自动隐藏。使用相同 `AreControlsVisible` 状态，播放器后端与渲染资源所有权不变。

Veyra 的名称、SVG/PNG/ICO 资源和生成方法见 [品牌说明](branding-20261114.md)。11 月 13 日已冻结候选和验收结果保持原身份；本次修改是其后的源码增量，旧候选不包含 Veyra 品牌和窗口标题栏联动。

### 实窗发现与修复

1. 只恢复 `OverlappedPresenter` 标题栏会留下覆盖页面头部的自定义标题按钮。现在同时恢复 `Window.ExtendsContentIntoTitleBar`，调用 `AppWindow.TitleBar.ResetToDefault()` 并重新应用系统主题；后续实窗布局正常。
2. 默认系统标题栏未可靠提供非客户区悬停事件。改为同时读取实际鼠标位置及窗口/客户区边界，并过滤因标题栏布局变化产生的静止指针事件。触摸/笔输入会清除旧鼠标悬停判断，窗口移动/缩放与实际按住仍独立保护。
3. `gui-run3` 隐藏后首次 Tab 出现进程异常退出。无搜索根的全局 `FocusManager.TryMoveFocus` 是当前证据最强的嫌疑，但没有应用崩溃堆栈，未宣称根因已由堆栈证实。改为可见性更新后直接对本页命名控件执行 `Focus(Keyboard)`；`gui-run4` 正向、反向和 Enter 激活均成功。保留失败轮日志、Windows 事件及 `tab-failure-review.md`。

真实触摸长按、笔输入和额外显示缩放组合没有实机验证；新增持续接触与窗口交互条件由策略测试覆盖，输入类型同步另经静态审查。静音循环测试视频仅用于上述交互检查，不构成长时间播放或音视频质量验收。
