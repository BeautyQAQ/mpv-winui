## 2. 固定协议与判据

从拉取前的完整备份恢复原性能编排脚本，其 SHA-256 仍为 `2BA0D1C8074D8EBED3D8DC6FC3CCEE956F7BC91B6D0E4571335CAB2BD644C316`。不回放旧阶段文档，保留旧 stash。使用相同已校验的 HEVC HDR10 / AV1 SDR 4K30 素材，每配置 S4/S5 各三组有采样/无采样配对，顺序交替，共 12 次；Debug 与 Release 的 GPU 工作负载顺序执行。

固定条件为 3840×2160 BGRA8 SDR、vsync 1、预热 2 秒、目标媒体稳态窗口 5 秒、目标 30 fps；唯一配对变量为读回请求间隔 0.1 秒/0。R1 要求 fps ≥29.4、VO 丢帧 ≤实际 PresentedFrames×1%、解码丢帧为零，输入未变且场景有效。缺失计数不作零，脚本退出零不替代性能判定。

随后独立执行三次 Debug 真实窗口 4K60 HDR→SDR 测量：预热 3 秒、稳态 15 秒，期间不做 Computer Use 截图、点击或额外像素采样。按目标帧率的同一 R1 规则检查 58.8 fps、VO 丢帧比例和解码丢帧；本轮只覆盖报告的实际表面、输出及短时窗口。Computer Use 的交互观察安排在测量之后，不混入稳态结果。

## 3. 实测结果

两配置各 12 次功能测量均完成，素材与各轮二进制前后哈希不变，每配置六组配对各自身份可比；S4 实际为 D3D11VA GPU 驻留，S5 实际为软件回退。

| 配置 / 场景 | 次数 | fps 范围 | R1 达标 | VO 丢帧总计 / 解码丢帧总计 | 各运行 Present 均值范围 |
|---|---:|---|---|---|---|
| Debug / S4 HEVC | 6 | 29.827～30.109 | 6/6 | 0 / 0 | 0.079～0.093 ms |
| Debug / S5 AV1 | 6 | 30.004～30.054 | 6/6 | 0 / 0 | 0.177～0.288 ms |
| Release / S4 HEVC | 6 | 29.773～30.160 | 6/6 | 1 / 0 | 0.078～0.117 ms |
| Release / S5 AV1 | 6 | 29.589～30.302 | 5/6 | 3 / 0 | 0.196～0.282 ms |

首轮共 **23/24 达标**。`S5-release-r1-sampled` 为有效但未达标运行：29.589 fps，实际呈现 148 帧，VO 丢帧 2 >148×1%=1.48，解码丢帧 0；Render p95 26.772 ms、最大 72.559 ms，Present 均值 0.196 ms。帧率本身达到 29.4，失败原因是呈现丢帧比例。对应无采样组达标，但其余两组有采样也达标，不足以将该单次失败确认为稳定采样开销。

未复现旧 RDP 12 次配对中 8 次约 10.6 fps 的低速状态；旧单次诊断 vsync 1 的 Present 均值约 79～92 ms，本轮各配对运行仅约 0.078～0.288 ms。上述结果与“呈现环境发生变化”一致，但不是严格证明远程协议为唯一原因。两次 VO 丢帧为 1 的 Release 运行仍按既定比例达标，不把达标写成所有运行零丢帧。

首轮汇总：`Debug-20261103-161529-58f1451a/comparison-summary.json`、`Release-20261103-161908-4c1d680e/comparison-summary.json`，逐行提取为 `all-initial-pair-rows.json`。额外安排 Release S5 三组交替顺序配对，保留首轮失败，不用补测覆盖原始 24 次结论；命令和脚本保存在本轮目录。

补充三对共六次全部达标，30.001～30.056 fps、VO/解码丢帧均为零，实际仍为 AV1 软件回退；有采样实际完成 36～37 次读回、无采样为零，位置推进约 5 秒、结束后画面非黑，输入/二进制不变。首轮的 2 帧丢帧未再次复现，根因保持未定；不能用补测抹去失败，也不能仅凭首次有采样失败把它确定归为读回开销。见 `Release-S5-followup/followup-summary.json`、`followup-rows.json`。

## 4. 真实窗口与 Computer Use

三次测量均使用相同固定 4K60 HDR10 媒体、实际 GTX 1060 D3D11VA GPU 驻留路径、BGRA8 SDR tone-map、调试层关闭；Windows HDR 未开启。实际表面均为 **1104×721**，而旧 RDP 表面为 1658×1084，因此窗口前后不是严格单变量比较，不能把窗口尺寸的影响计入纯协议差异。

| 轮次 | fps | VO / 解码丢帧 | Render p95 / 最大 | Present 均值 | 60 fps 对应 R1 |
|---|---:|---|---|---:|---|
| 1 | 58.221 | 27 / 0 | 2.459 / 140.275 ms | 0.107 ms | 未达标 |
| 2 | 59.964 | 0 / 0 | 2.034 / 4.475 ms | 0.114 ms | 达标 |
| 3 | 60.029 | 0 / 0 | 1.937 / 5.749 ms | 0.108 ms | 达标 |

旧 RDP 窗口为 32.000 fps、VO 丢帧 423、解码丢帧 0、Present 均值 29.283 ms。本轮改善明显，但首轮 58.221 fps 低于 58.8 且呈现丢帧比例超限，不能写成三轮性能全过。首轮存在 Render 最大 140.275 ms 的尖峰，不能仅凭后两轮通过就消除首轮记录或认定冷缓存为已证实根因。

三次探针报告的 `Passed` 只表示测量、画面检查与关闭流程通过；性能独立按上表判定。均正常退出，renderer/session 释放、重复关闭安全通过，历史原字节恢复且 SHA-256 一致。详见 `window-summary.json`、`window-cleanup.json` 和各 `window-4k60-r*/` 原始目录。

Computer Use 另外启动保留的 Release 应用（进程 20052），通过实际地址框打开同一 4K60 素材，取得动态彩条/移动图案画面和推进的时间轴；信息面板显示 HEVC 3840×2160 / 10 bit / 60 fps、D3D11 硬解 / GPU 纹理传递、HDR10/PQ→SDR，观察时累计解码与呈现丢帧均为零。

已验证暂停至 15.567 秒、暂停时后退 15 秒到 0.567 秒、全屏至 1920×1080、Esc 返回窗口、继续推进至 16.117 秒及再次暂停，随后通过标题栏关闭。首次 `type_text` 未产生可见输入，改用同一 Computer Use API 的可访问性 `set_value` 后路径可见、打开成功；退出全屏动画后一次输入遇到 `window bounds changed`，重新绑定并观察后恢复，未将工具状态错误记为播放器缺陷。

正常退出码 0，日志确认 render context、EGL/SwapChain/D3D11、mpv session、主窗口按顺序释放。`gui-observations.json` 保存各观察时点的 UI 状态与截图标识，`gui-process-identity.json`、`gui-exit.json` 和 `gui-session.log` 保存进程/退出/资源证据；这些交互不计入前述测量。最后 `closure-verification.json` 确认播放器和 testhost 均消失、六项登记二进制与固定输入未变、最近记录恢复至原 SHA-256 `024E43BF323BD590229148F46E831F64EB114AAC28F44E8F6C9CA7C0932A408F`。

## 5. 结论与限制

本轮结论是 **UU console 会话下，GTX 1060 的开发机端呈现相对此前 RDP 明显改善**：固定 4K30 的旧 Debug 为 4/12 达标，本轮 Debug 为 12/12；未改建的旧 Release 首轮为 11/12，S5 补测 6/6。4K60 窗口由旧 32 fps 改善至本轮 58.221～60.029 fps，主要区别是旧的长 Present 等待本轮未出现。不能将此前 10.6 fps 直接解释为 GTX 1060 渲染算力不足。

仍保留两类未达标：首轮 Release AV1 有采样的 2 帧 VO 丢帧，以及第一轮真实窗口的 27 帧 VO 丢帧/140.275 ms Render 尖峰。用户在收到上述实际结果与限制后接受当前结果，要求本部分标记全部完成并提交推送；两项作为已接受观察保留，不再阻塞本机调查收口。不修改产品 vsync、原始 R1 阈值或失败计数，完成状态不表示每次测量均达到 R1。本轮没有全量回归、长测或新候选发布声明。

UU 客户端实际收到的编码帧率、网络丢包、延迟、音画同步及远端显示体验未由开发机呈现计数直接测量；截图也不证明持续帧率。既有 940M/Intel 机器原生崩溃与候选包 GUI 缺口独立保留，本轮测试的是本机构建目录，不能替代该候选的最终目录验收，不关闭 P3-00，也不替代长期、其他硬件或物理 HDR 验收。
