## 1. 实现与控制契约

`IPlayerBackend` 新增 `StopAsync` 与 `SetSpeedAsync`，`PlaybackState` 新增 `IsStopped` 与 `Speed`。默认速度为 1.0，允许 0.25～4.0；非有限或越界输入拒绝提交。会话观察原生 `speed`，界面只显示回传值，停止、换片和 EOF 不重置倍速；不要求重启后保留倍速。

停止分成提交屏障和卸载确认。原生接受 `stop` 请求时，后端使当前加载等待及停止前排队的加载失效，并隔离旧媒体事件；此时不提前发布“已停止”。命令回复后继续检查原生 `path`，确认不可用才清空位置、时长、轨道、媒体信息和缓冲，并回传 `IsStopped=true`。当前地址保留，播放按钮可从头重新打开；初始空闲或重复停止同样可确认，不依赖必然出现 `EndFile`。

这一边界来自本地锁定版本 mpv 源码核对：`mpv_command_async` 返回成功只表示验证并排队；`cmd_stop` 设置 `PT_STOP`，音视频卸载发生在之后的播放收尾；`filename` 在卸载和 `EndFile` 通知后清除。源码核对输入位于 `artifacts/p1-02-attribution/mpv-full/` 的 `include/mpv/client.h`、`player/command.c` 与 `player/loadfile.c`。`completeAfterSubmission` 内部模式使取消与原生提交有明确先后：提交前取消不执行停止，提交后调用者可以结束等待，内部仍完成卸载确认和状态回传。

加载提交由独立门串行协调，停止不等待媒体 `FileLoaded` 或网络返回；停止期间和停止后拒绝 seek。ViewModel 的媒体操作版本与播放控制版本分开，停止使旧加载、seek、播放/暂停和轨道命令的迟到成功/失败失效；旧停止或 EOF 的 UI 事件不取消新加载。加载后的媒体信息/轨道查询也检查版本，停止后不回填详情或最近打开记录。

停止确认后，页面显式调用 `RequestRedrawAsync`，让现有 Render API/ANGLE/D3D11 路径呈现空闲黑帧，不依赖卸载时必然产生新 `FRAME` 通知。页面同时停止未提交的时间轴节流、结束拖动并禁用停止中的时间轴。后端、渲染器和会话仍沿用原生命周期，重播复用同一 core 与 render context。

UI 增加停止按钮和九档倍速菜单：0.25、0.5、0.75、1、1.25、1.5、2、3、4 倍。菜单打开时暂停控制条自动隐藏，并避免页面空格/左右键抢占菜单输入。宽窗口单行、窄窗口两行的控制区布局已实现；本轮仅实际验证默认宽窗口，窄窗口仍未验证。
