> 架构基线：[技术方案第 14 节](../architecture.md#14-分阶段实施计划)

## 1. 目标与承接关系

Phase 0 已在声明范围内通过，证明了 libmpv、Render API、ANGLE/EGL、D3D11 和 SwapChainPanel 的正式路线。Phase 1 承接现有实现，完成生产级播放基础的契约、生命周期、媒体覆盖和发布验证，不重建已通过的基础链路。

本计划对应 `docs/architecture.md` 第 14 节的六项目标：模块结构与资源所有权、后端抽象与状态模型、命令/事件/错误、轨道/媒体信息/缓存/日志、设备/页面/退出生命周期、原生依赖打包/哈希/许可证。

Phase 0 已有的命令队列、事件映射、恢复租约、终态隔离、原生依赖清单和发布脚本是本阶段的输入。每个工作包先核对实现与既有证据，仅补实际缺口；已有通过项可以引用证据，不为满足清单重复实现。

本阶段不自动纳入完整播放器 UI、倍速交互、最近打开持久化、时间轴预览、OSD 视觉改造或播放列表产品功能。字幕和 HLS 工作限于现有播放基础的正确性与验收，不新增字幕面板、认证界面或自适应码率产品策略。上述交互能力按原架构留待 Phase 2 规划。

## 2. 基线与验收边界

- Phase 0 范围与历史验收以 [P0-11 记录](evidence/P0-11-01-phase-0-acceptance.md) 为准；TS 补丁以 [TS 跳转记录](evidence/ts-seek-keyframe-2026-09-12.md) 为准。
- 本轮重新验证的源码基线为 `f793d0b`。Debug 显式提供固定素材后 188 通过、0 跳过；Release 日常配置 184 通过、4 跳过；两种构建均为 0 警告、0 错误。具体命令、素材、日志和报告见 [P1-00 基线记录](evidence/P1-00-01-baseline-and-release-entry.md)。
- Debug 合成 TS 对照目标为 `2,4,7,11,16,21,25,9` 秒；产品硬解/软解的参考帧错误均为 0，关闭选项的对照为 192，最大落点偏差 21.33 ms。历史 LG 素材的 11/12 ms 不能作为不同素材、目标集合的当前结果。
- 原生硬件报告验证解码路径与非黑像素，不包含流畅度断言。本轮 HEVC/AV1 报告分别记录 105/110 次呈现掉帧，因此 188 项通过不能解释为性能验收通过；P1-01 单独复核性能。
- 源码回归状态和已分发测试包是两个对象。现有测试包的构建提交、生成时间、文件哈希和复测证据仅在 [发布状态](release-status.md) 维护；源码 HEAD 前进不会自动生成新包。
- 双显示器/跨屏、长时间稳定性、真实触屏及额外 DPI/硬件矩阵按已有决定延后，不成为本阶段新阻塞，也不得写成已支持。P1-01 的短时性能复核不等同于长期稳定性验收。

## 4. 工作包细则

### P1-00：基线、计划与发布入口

**边界与输入**

读取 Phase 0 记录、现有实现、最近提交、实际测试报告和已有外机包。建立下一阶段计划并清理当前状态中的过时结论。本包不要求新增 GUI 验收，也不重新打包或分发。

**产物**

- `phase-1-plan.md` 与 `phase-1-progress.md`。
- `evidence/P1-00-01-baseline-and-release-entry.md`，关联本轮实际回归与报告。
- `release-status.md`，给出唯一的已分发包入口和来源，并区分源码基线与包内提交。

**验收**

- Phase 0 完成范围、延后矩阵、当前回归数量和素材差异均有出处，不把历史快照当作当前结果。
- 六个工作包均有边界、依赖、产物及可判定验收；下一包明确为 P1-01。
- 发布入口指向已存在的包，记录其实际构建身份；不存在“文档更新即已重新发布”的表述。
- HEVC/AV1 功能测试和性能结论分开记录，历史性能尾项保留为待复核。

**必要验证**

核对文件路径、Markdown 链接、源码/产物身份、既有 TRX 和硬件报告；检查 UTF-8 无 BOM。纯文档修改无需重复运行已完成的构建测试。

### P1-01：固定媒体回归与性能场景复核

**边界与输入**

将已有 WAV/Y4M、HTTP/HLS、4K HEVC/AV1、PQ 渐变和合成 TS 输入整理为可再生成、可定位的回归集合。复核 GTX 1060 上曾记录的应用内 4K60 SDR tone-map 慢帧场景，以及本轮短原生测试中的呈现掉帧；不先归因于 GPU、Debug 或采样开销。

**产物**

- 素材清单：来源/生成命令、哈希、编码、时长、色彩、适用测试和环境变量。
- 场景清单：GPU/驱动、构建配置、输出模式、窗口尺寸/可见性、预热与采样区间。
- 独立的功能结果与性能报告；必要的局部修复及修复前后同条件证据。

**验收**

- 固定输入可重建或由已记录哈希校验；测试不依赖可能失效的公网媒体，私人媒体不进入 Git。
- 素材驱动测试实际执行，所有跳过项均有原因；Debug/Release 使用相同输入时可以比较结果。
- 合成 TS 产品配置无参考帧错误；关闭补丁的对照仍覆盖原问题。记录全部目标及落点，不将不同素材的误差上限混用。
- 历史慢帧场景有当前版本、相同 GPU/输出模式的复测结果。记录自然呈现 FPS、解码/呈现掉帧、Render/Present 耗时及采样条件，并做无采样对照，区分测试节奏与应用吞吐。
- 每个性能场景在测量前记录目标帧率、稳态区间与判定规则。支持 4K60 的结论必须由对应场景的自然呈现数据支持，不能由解码器名称或功能测试通过推断。
- 若低吞吐可复现，先区分实现/配置缺陷、测试调度和硬件限制。实现缺陷须修复并同条件复测；已解释的测试或硬件限制须附自然播放对照数据、适用范围和结论，不能据此擅自改变既有验收承诺；尚未解释的异常保持待验证。其他 GPU、不同输出路径的流畅结果不能替代关闭该场景。

**必要验证**

先跑涉及固定输入的集成测试和单独性能场景；代码有修改时执行相关回归。工作包收尾运行 x64 Debug/Release 构建与全量测试，并保留显式素材运行结果。短时性能验证不扩展成已延后的跨屏或长期测试。

### P1-02：状态、错误与命令契约

**边界与输入**

审计现有 `IPlayerBackend`、应用状态、命令队列、事件快照和 UI 派发。以现有播放命令为对象，补齐已发现的语义缺口，不增加新的产品控制入口。

**产物**

- 状态/事件契约表：打开、缓冲、播放、暂停、seek、EOF、可恢复错误和不可恢复终态。
- 请求关联、取消/超时、迟到回复、换媒体隔离及错误分类记录。
- 与实际缺陷或契约边界对应的实现修复、回归和日志证据。

**验收**

- UI 不依赖 mpv 原始属性名、指针或原生结构；状态与错误有明确的唯一来源。
- 连续加载、seek 竞争、命令等待取消/超时、EOF 重播和加载失败后恢复行为符合契约；取消等待不被误记为撤销已进入 core 的命令。
- 缓冲结束不会因队列丢弃或迟到事件永久丢失；旧媒体事件不覆盖新媒体状态。
- 不可恢复终态拒绝播放修改，迟到成功回复不能清除错误；日志区分加载、播放、渲染和初始化错误，并保留诊断原因和 URL 脱敏。
- 仅补实际缺口，已有回归能覆盖的行为引用现有证据，不增加仅镜像实现的测试。

**必要验证**

运行 Abstractions、LibMpv 和 App 中相关状态/命令测试；涉及真实事件次序的变更使用 P1-01 固定媒体集成复核。收尾执行受影响项目构建与测试。

### P1-03：生命周期、页面重建与退出

**边界与输入**

承接现有恢复租约、一次自动重建、失败终态和释放协调。核对 UI、命令/事件、渲染三个执行域及共享 core 的所有权；验证真实页面卸载/重新挂载，不把同一 core 的原生上下文重建等同于页面生命周期已验收。

**产物**

- 资源所有权与启动/关闭/恢复顺序记录。
- 页面重建、恢复中关闭、加载中关闭及重复故障的场景记录。
- 必要修复、应用内证据和资源释放结果。

**验收**

- `SetSwapChain` 在 UI 线程，EGL/OpenGL 与渲染资源由渲染线程管理；执行域间无同步循环等待。
- render context 先于 core 释放，回调注销前所有者仍有效；重复关闭幂等，关闭后排队事件不更新页面。
- 播放和暂停状态下页面重建、渲染重建均保持正确媒体/轨道；暂停场景核对稳定位置和真实像素，不仅检查 Present 计数。
- 首帧再次故障、重建失败、恢复中换媒体/关闭均不会恢复旧媒体或清除终态错误；退出完成且没有遗留活动会话。
- 证据明确区分故障注入和真实驱动重置。跨屏、实际 TDR 与长期资源趋势若未测，保持未验证，不借本包扩大硬件承诺。

**必要验证**

运行相关生命周期/恢复测试，以及现有应用内恢复脚本支持的必要场景；为真实页面生命周期缺口补相应验证。只有代码受影响时再运行对应项目及解决方案回归，不要求重新执行已延后的人工矩阵。

### P1-04：视频 HLS、字幕与媒体信息验收

**边界与输入**

Phase 0 的本机 HLS 证据来自 ADTS AAC 分片，不能替代视频 HLS 渲染验收。本包以固定本机视频 HLS、现有字幕/音轨接口和媒体信息模型为对象，不自动加入自适应码率策略、直播追帧、播放列表 UI 或字幕面板改造。

**产物**

- 可再生成的视频 HLS 和含音轨/字幕的固定样本及清单。
- 播放、跨分片 seek、轨道切换/关闭、错误恢复和媒体信息变化记录。
- 后端及真实渲染集成证据；发现的解析、事件或字幕呈现缺口修复。

**验收**

- 本机视频 HLS 在正式 Render API 链路显示实际变化画面，暂停、跨分片 seek、EOF 和错误后重新加载符合 P1-02 契约。
- 已有字幕/音轨查询与选择接口对固定多轨素材返回正确 ID、语言、选择状态；字幕选择/关闭的实际像素或目视结果与状态一致，不只验证轨道列表。
- 换媒体不保留上一媒体的轨道、缓存或色彩信息；EOF 后保留的信息符合现有契约，未知值与零值不混淆。
- 缓冲与媒体信息在真实事件下更新；高频属性不使 UI 持续排队，日志保持脱敏。
- 未覆盖的字幕格式、HLS 类型及 HDR 素材类别明确登记，不将单一样片通过泛化为全部兼容。

**必要验证**

运行相关本机 HLS、轨道/信息解析、原生集成与渲染验证；如现有接口无法支持某种媒体，先记录明确缺口再限定修复。变更收尾执行受影响项目回归。

### P1-05：发布可复现与 Phase 1 验收

**边界与输入**

在前述工作包通过后，以最终源码和真实发布目录核对生产级基础。沿用锁定依赖和现有发布脚本；本包是后续工作，不意味着 P1-00 需要生成新包。

**产物**

- 源码提交、原生源码/补丁、工具版本、DLL 哈希、许可证与最终包的对应清单。
- 最终构建/测试、发布烟雾、最终目录启动播放和正常退出证据。
- Phase 1 验收记录、支持范围/已知限制；更新唯一发布入口。

**验收**

- x64 Debug/Release 构建无错误，测试无失败；素材驱动测试实际运行的结果与默认跳过结果分别记录。
- 发布目录四 DLL 与清单匹配，x64、Client API、实际加载和会话创建/销毁烟雾通过；无旧路线 DLL 或外部 `mpv.exe`。
- 发布步骤从已记录输入可复现，许可证/源码通知完整；不能用开发输出目录的成功代替最终发布目录验证，也不在未证明时宣称二进制逐字节可重现。
- P1-01～P1-04 每项验收均有可复核证据，最终产物运行没有未解决的范围内阻塞；性能与硬件结论保留场景条件。
- `release-status.md` 如实指向最终已验证产物，源码提交、包内提交和外机复测身份不混用。

**必要验证**

执行最终 x64 Debug/Release 构建与全量测试，使用显式素材复核要求的原生场景；运行发布脚本、原生闭包/许可证验证和最终目录烟雾，再验证启动、固定媒体播放和正常退出。只有完成这些项目后才可将 Phase 1 标记通过。

## 5. 状态与证据规则

- 工作包状态使用“未开始 / 进行中 / 待验证 / 通过 / 阻塞 / 失败”；代码已存在或构建通过不能单独使工作包通过。
- 开始时记录输入提交、范围与必要验证；结束时记录实际命令、结果、提交、证据和剩余限制。
- 已有通过证据可以承接；输入、实现或验收条件改变时明确需要重验的部分，不覆盖失败历史。
- 范围内验收失败必须修复或保留未通过状态；用户已决定延后的人工矩阵另表维护，不能擅自改成新闸口，也不能改成已通过。
- 新包只在实际生成并完成对应验证后更新发布入口。进度文档与架构说明的更新不代表已发布。
