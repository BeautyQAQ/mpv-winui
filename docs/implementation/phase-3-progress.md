## 1. 当前结论

2026-11-04 后续完成：用户确认本设备不要求 HEVC 硬解或软件 4K60 性能。重置 Computer Use 后身份修复生效，当前 Release 的播放、暂停/跳转、全屏/Esc、停止重播、倍速、换片、最近记录重启恢复及不自动播放、正常退出已验收，三轮退出 0，资源释放和历史恢复。H.264 无截图稳态测量为 1080p30 29.9858 fps、720p60 59.9993 fps，解码/呈现丢帧增量均 0；1080p60 补测 59.0630 fps、呈现丢帧 19，未达到补充 1% 目标，限制保留。本机旧故障跟进按该兼容范围完成，见 [本机 GUI 与 H.264 验收](evidence/P3-00-06-940m-gui-and-h264-acceptance.md)。旧严格 runner 结果不改写，旧候选不含修复，候选更新/最终目录工作独立保留。

同日 GUI 补验前的修复结果：按实际 Haswell 适配器在创建 render context 前禁用 HEVC 硬解，保持 H.264 的 D3D11 GPU 纹理路径，并修正探针清理顺序、EOF 可缺省属性和短片采样。最终 Debug/Release 构建均 0 警告/错误，默认各 538/0/11，显式兼容清单各 547/0/2，192 项构建输入及 22 处素材/清单哈希一致；11 项真实应用恢复/关闭及 H.264、原 4K HEVC 自然到 EOF 均通过，正常退出并释放会话。严格 runner 因两项跳过保持 `allCommandsPassed=false`；原 4K60 条件约 12.42 fps，未满足当时的性能前提。Computer Use 当时仍报告 Switch Desktop 归属错误。详见 [修复记录](evidence/P3-00-05-940m-hevc-compatibility-fix.md)；后续 GUI 通过与本设备范围调整以上方完成记录为准，原始结果不改写。

同日修复前复验：用户确认当前就是 940M / Intel HD 4600 原设备并授权验证。原素材及清单 22 处哈希、旧 Debug Rendering 输出 144 份 DLL 均匹配；同机驱动已更新，未回退或改变设置。原二进制独立自然播放再次在 `RenderContextRender → PerformanceProbe.Render` 出现 `0xC0000005`，修复前最新 Debug/Release 显式轮同样复现；两配置默认各 525/0/9。Computer Use 的 `sky` 和 `cua_repl` 都将播放器窗口归属识别为 Switch Desktop 并拒绝绑定。原生故障是实际复现的问题，不能当作残留任务删除；完整结果和收尾见 [原设备复验](evidence/P3-00-04-940m-device-revalidation.md)。下述 11 月 3 日的“旧设备暂不可访问”为当时边界。

2026-11-03 补齐 GTX 1060 / UU / console 本机完整回归。前三次完整轮分别暴露 runner 环境变量空值残留、最近记录测试缺少串行 UI 上下文、停止/倍速测试提前结束属性等待三项验证问题，失败均保留；修正工具及测试，产品源码与项目配置未改。最终 Debug/Release 构建各 0 警告/错误，默认各 525 通过/0 失败/9 条件跳过，显式各 534 通过/0 失败/0 跳过，189 项构建输入及 22 处素材/清单哈希前后一致。实际候选 DLL 另以不重建方式完成 534/0/0，113 项产品输入匹配原候选，35 份临时替换文件均恢复，693 项主 ZIP 和 290 项源码内容及哈希仍一致，历史未变、无残留进程；详见 [本机记录](evidence/P3-00-03-current-machine-regression.md)。用户确认旧 940M / Intel 设备暂不可访问，先完成本机验证；旧原生崩溃与挂起只能登记为本机未复现，P3-00 整体继续待验证。
