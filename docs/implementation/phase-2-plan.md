## 1. 目标与范围

Phase 0 与 Phase 1 已在声明范围内通过。Phase 2 承接现有进程内 libmpv、Render API、ANGLE/D3D11 与 WinUI 3 实现，补齐日常播放器交互；既有状态、命令、错误、生命周期和发布边界继续生效，不重建播放或渲染路线。

本阶段按依赖完成停止与倍速、最近打开持久化、时间轴目标时间预览和手势反馈，随后完善控制条、OSD、轨道面板、窗口与触控交互。首个实现工作包为 P2-01；后续工作包先核对现有能力，只补实际缺口。

时间轴预览指拖动或悬停时显示目标时间，不包含缩略图解码、缓存或图片预览。播放列表、自适应码率产品策略、媒体库、浏览器认证/Cookie 管理等不在本计划范围内。最近打开沿用单媒体打开流程，不因此引入队列播放。

## 4. 工作包细则

### P2-00：计划与基线

核对架构、Phase 1 完成范围、当前源码与发布包身份；建立 P2-00～P2-05 的依赖和验收条件。仅补文档及解决方案文档索引，无新增发布。

验收：阶段入口互相可达；源码测试与包身份分别记录；PERF-02 和硬件/长期验证未被写成通过；新增文本为 UTF-8 无 BOM，解决方案可被 `dotnet sln mpv-winui.slnx list` 解析。纯文档工作不重复运行代码回归。

### P2-01：停止与倍速

新增强类型后端控制，保持 `App → IPlayerBackend` 边界；实际状态经后端事件回传，UI 不因命令已提交就提前宣称完成。

| 控制 | 契约 |
|---|---|
| 停止 | `StopAsync` 卸载当前媒体，清除位置、时长、轨道、媒体信息和缓冲状态；保留当前地址供用户再次播放。停止后视频不继续播放，不残留上一媒体的进度与轨道展示。 |
| 加载中停止 | 结束正在等待的加载，不把用户停止显示为加载错误；停止后的迟到加载结果和过时 seek 不能重新推动播放状态。 |
| 停止后重播 | 播放入口可重新加载保留的地址；空地址时保持空闲，不提交无效媒体请求。重复停止保持可预测的空闲状态。 |
| 倍速 | 支持 0.25～4.0 倍，默认 1.0 倍；UI 提供常用值与当前值。越界或非有限输入不提交原生命令。 |
| 倍速生命周期 | 本次运行内跨停止、换片及 EOF 保留；不要求跨进程持久化。后端回传实际值，界面据此更新；状态清理不能把已选择倍速意外重置。 |
| 取消与失败 | 沿用既有请求关联、取消/超时、错误分类和终态保护。取消、原生失败或迟到回复不得伪造已停止/已调速的成功状态。 |

验收：

- 播放中、暂停中、加载中及 EOF 后均覆盖停止；重复停止、停止后重播、停止与 seek/加载竞争有可复现验证。
- 清理后的位置、时长、轨道、媒体信息和缓冲一致；保留地址及倍速符合上表，旧事件不能复活已停止媒体。
- 倍速边界、非法值、成功事件回传及停止/换片/EOF 保留由逻辑测试和真实 libmpv 会话验证。
- 控件状态与后端一致，停止和倍速入口可操作，既有播放/暂停、seek、轨道选择和错误恢复不退化。
- 完成 x64 Debug/Release 构建与相关测试；收尾跑默认全量回归并如实记录跳过项。媒体依赖场景显式提供输入后执行；应用操作证据与逻辑/原生测试分开记录。

### P2-02：最近打开持久化

沿用已有“最近打开”行为和 10 条上限，新增用户本地存储、启动恢复与清空。成功打开后才更新历史；继续按既有规则去重和排序，本地路径与 HTTP/HTTPS 地址均走同一打开校验。

验收：正常重启可恢复顺序与条目；重复打开只保留最新位置，超过上限淘汰最旧条目；清空后重启仍为空。缺失、损坏或不可写的历史文件不阻止播放器启动和打开媒体；保存采用可恢复的写入方式，失败可诊断。地址不得作为 shell 命令，日志继续脱敏，存储只保留恢复历史所需字段。测试覆盖保存/读取/清空、格式异常和失败路径，并执行一次真实应用重启流程。

### P2-03：时间轴预览与手势反馈

基于现有时间轴和手势协调服务，显示悬停/拖动的目标时间以及 seek、音量等操作结果。媒体实际位置与未提交的预览位置分离；沿用既有 seek 节流和请求归属，不在 XAML code-behind 分散实现竞争策略。

验收：鼠标点击/拖动、键盘及合成触控输入给出一致目标；越界目标夹取到合法范围，未知时长和不可 seek 媒体有正确禁用状态。取消拖动、打开新媒体、停止和窗口失焦后预览及时清除；迟到位置事件不覆盖当前拖动预览。手势冲突、阈值和浮层优先级通过协调层回归，操作结束后反馈按规则消失。本包不实现缩略图预览，合成触控通过不等于真实触屏通过。

### P2-04：播放器界面完善

依据架构补齐大尺寸底部控制条、字幕/音轨选择面板、OSD 与详细信息、自动隐藏、窗口及全屏体验。承接已有轨道和媒体信息，不增加外部字幕下载、字幕检索或其他产品范围。

当前实现和实际证据见 [P2-04 验收](evidence/P2-04-01-player-interface.md)。控制条以 1100 宽度阈值切换单行/双行，主控件至少 48 像素高；初版 720×560 窗口的轨道内容区过矮，改为 720×640 后完成最小窗口、轨道滚动、焦点/自动隐藏及退出清理复验。本包在声明的本机功能范围内通过，触屏和额外 DPI 等边界仍按原计划保留。

验收：常用打开、播放/暂停、停止、倍速、seek、音量/静音与轨道切换入口完整，禁用状态可理解；加载、缓冲、EOF 和错误反馈不互相覆盖。窗口/全屏切换后布局与输入保持一致；鼠标、键盘焦点、浮层打开和操作中状态遵守自动隐藏规则；Esc 按浮层优先级处理。验证最小窗口、长媒体标题和长轨道名称，触控目标与手势冲突可测试。实际触屏和额外 DPI/显示器矩阵仍单列待验证，不据自动化结果关闭。

验收：x64 Debug/Release 构建及默认全量回归无失败，显式素材回归实际执行且输入可定位；每个交互包的验收条件有证据映射，失败历史和未验证范围保留。真实应用操作覆盖键鼠和窗口流程；真实触屏、硬件矩阵、长期稳定性和 PERF-02 状态分别记录。若生成新的测试包，按现有发布流程独立校验来源、快照、原生/托管许可证、最终目录运行和 ZIP 内容，再更新发布入口；未生成新包时保留 Phase 1 包身份。
