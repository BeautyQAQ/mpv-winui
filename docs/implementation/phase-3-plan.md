## 1. 目标与承接关系

Phase 0～Phase 2 已在各自声明范围内通过。当前源码已包含停止与倍速、最近打开持久化、时间轴数字预览、手势反馈和完整播放器界面；相关实现与验收见 [Phase 2 进度](phase-2-progress.md) 和 [P2-05 验收](evidence/P2-05-01-phase-2-acceptance.md)。Phase 3 承接现有架构及功能，建立可复核的当前版本基线、候选产物、性能和稳定性证据，并在声明范围满足后完成最终发布验收。

本轮用户要求是“建立当前版本基线，生成新候选测试包”。执行范围为 P3-00：固定源码与素材身份、Debug/Release 默认和显式素材回归、候选包生成、最终目录运行及内容核验。后续性能、长时间播放和硬件工作分别登记，不因候选包生成而记作通过，也不自动成为本轮额外阻塞。

继续使用进程内 libmpv、Render API、ANGLE/EGL、D3D11 和 WinUI 3，发布目标仅为 `win-x64`。本计划不增加播放列表、媒体库、自适应码率产品策略、缩略图预览、外部字幕下载或新的播放内核。

## 3. 工作包与顺序

2026-11-04 原设备已可访问，原故障复现及转储材料保留于 [原设备复验](evidence/P3-00-04-940m-device-revalidation.md)。有效挂起转储已分析，当前源码通过旧 Intel HEVC 软件回退恢复稳定播放，见 [修复记录](evidence/P3-00-05-940m-hevc-compatibility-fix.md)。随后 Computer Use 身份修复生效，本机 GUI、正常退出及 H.264 常见负载已验收；用户明确取消本设备 HEVC 硬解与软件 4K60 性能前提，详见 [范围和完成记录](evidence/P3-00-06-940m-gui-and-h264-acceptance.md)。以上“暂不能访问”为 11 月 3 日当时状态；本机旧故障跟进已完成，候选更新与最终目录验收分别保留。

## 4. P3-00 本轮验收

| 验收项 | 可判定条件 | 证据 |
|---|---|---|
| 源码与环境身份 | 记录起始提交、工作区差异、SDK/PowerShell/系统、实际构建输入哈希；测试和 GUI 对应正确二进制 | 本轮身份清单与构建日志 |
| 素材输入 | 固定所需 HLS/字幕/多轨、HEVC/AV1/PQ、TS seek 和性能输入，记录生成参数、工具及素材哈希；不依赖不稳定公网地址 | 素材清单及输入环境变量映射 |
| 两配置回归 | x64 Debug/Release 构建无错误；默认全量无失败，跳过按实际列出；显式素材场景实际执行，失败和复验分别保留 | 原始构建/测试日志、TRX 和逐项汇总 |
| 候选内容与来源 | 生成独立 Release `win-x64` 自包含目录，记录源码快照和包身份；原生依赖与锁定清单一致，许可及源码通知完整，无旧路线产物 | `build-info.json`、源码快照、原生/许可核验 |
| 最终目录运行 | 从候选目录验证实际画面、播放/暂停、停止/重播、倍速、换片、最近记录保存与重启恢复、正常退出；核对资源释放和进程结束 | 操作记录、会话日志、退出码与进程身份 |
| 封包与登记 | 验收日志保存到包外，ZIP 条目逐项匹配目录；包/源码 ZIP 及清单哈希可核验；实际完成后更新唯一入口并明确候选范围 | 封包报告、SHA-256、[发布状态](release-status.md) |

应用验证前保存用户最近记录，退出后按原内容恢复，不能将测试媒体留在用户历史里。GUI 证据须区分可见画面、UI 状态和日志；如果桌面无法访问或某场景未执行，记录具体限制，不能仅用单元测试替代最终目录验收。

既有恢复探针、发布闭包与素材脚本优先复用，仅为候选包身份、复现或实际发现的缺口修改工具。各轮回归使用对应的已固定构建；若两轮之间重新构建，分别保存输入和二进制身份，不能混写为同一次构建。测试期间修改编译输入须重建并重新验证受影响范围。后补文档与包内构建时快照的差异单独说明，不覆盖原始身份记录。

## 5. 后续工作与完成规则

P3-01 沿用 [P1-01 固定场景](evidence/P1-01-01-fixed-media-and-performance-scenarios.md)，记录 GPU、驱动、显示/输出模式、窗口状态、远程或本机会话、调试层、预热与稳态区间。已有功能测试的瞬时丢帧或复验通过不直接解释根因；没有判定条件的测量保持“已测量，未判定”。

2026-11-03 用户在获知本轮实际结果及限制后，要求 GTX 1060 / UU 调查全部完成并提交推送；该包采用“完成（本机范围，用户接受）”登记，见 [接受记录](evidence/P3-01-02-gtx1060-uu-remote-performance.md#6-用户接受与完成登记)。这是对调查结果的接受，不将原始 R1 未达标改成通过，不扩展其他设备、长期或发布范围。

P3-02 在当前播放和页面恢复能力上增加连续场景，关注挂死、异常退出、未释放会话、资源持续增长和恢复后旧媒体回写。次数和时长在执行前登记；有限循环不能写成长时间稳定性或全部硬件通过。发现产品缺陷时修复并在同条件下复验。

2026-11-05 同步时补回 10 月 29 日的 [RTX 3070 复测](evidence/P3-00-02-rtx3070-retest.md)和 [P3-02 短测](evidence/P3-02-01-continuous-short-test.md)。连续测试使用两份生成素材 2 轮、两份用户视频 1 轮，每次推进 1.5 秒、每进程上限 180 秒；分别完成 24/12 动作并正常退出/释放。历史结果对应当时源码，当前合并版本须单独验证；两小时长测和资源趋势继续暂缓，不自动恢复执行。

P3-03 只汇总有实际证据的能力。最终目录、源码、测试和分发文件必须互相对应；更新包后重新核验必要场景。各工作包使用“未开始 / 进行中 / 待验证 / 通过 / 失败”并记录限制，只有已声明验收全部满足才关闭对应工作包。P3-00 通过不关闭 PERF-02，也不表示整个 Phase 3 已通过。
